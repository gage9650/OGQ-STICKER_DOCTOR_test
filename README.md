# 🩺 OGQ Sticker Doctor

> 초보 스티커 제작자가 **업로드 전에 문제를 찾아보고, 무엇을 어떻게 고쳐야 하는지 확인할 수 있도록 돕는 스티커 검사 도구**입니다.

[배포된 서비스 바로가기](https://ogq-sticker-doctor-bnfuonxjgsxocjwtvi9e9h.streamlit.app/)

---

## 1. 프로젝트 소개

스티커를 처음 만드는 사람은 이미지를 만드는 것보다도 **업로드 직전의 확인 과정**에서 자주 막힙니다.

“크기는 맞는지”, “배경은 제대로 투명한지”, “여백이 너무 넓지는 않은지”, “AI가 말하는 문제가 실제 이미지의 어디인지”, “그래서 무엇부터 고쳐야 하는지”를 하나씩 직접 확인해야 하기 때문입니다.

**OGQ Sticker Doctor**는 이 과정을 한곳으로 묶었습니다.

이미지의 기술 규격을 먼저 확인하고, OGQ 시장의 공개 콘텐츠를 참고해 시장 차이를 살펴본 뒤, Gemini 기반 AI가 문제의 위치와 원인, 개선 방법을 설명합니다. 마지막에는 준비도 점수와 우선순위, PDF 리포트, 히스토리와 리뷰까지 연결해 **“검사 → 이해 → 수정”**의 흐름을 만들었습니다.

---

## 2. 우리가 해결하려고 한 문제

### 규격을 확인하기 어렵습니다

초보 제작자는 메인 이미지, 스티커 이미지, 탭 이미지의 규격을 일일이 확인해야 합니다.

### 오류를 찾아도 수정 방법이 막막합니다

“규격 오류”, “여백 문제”처럼 결과만 알려주면 사용자는 실제 이미지에서 어디를 손봐야 하는지 다시 찾아야 합니다.

### AI 피드백이 많아도 행동으로 이어지지 않을 수 있습니다

실제 사용 과정에서 AI 피드백을 확인하는 화면이 주요 이탈 지점으로 확인되었습니다. 그래서 기능을 더 추가하기보다 **문제 위치와 핵심 개선 방법이 한눈에 들어오도록** 정보 구조와 가독성을 개선했습니다.

## 3. 핵심 기능

| 기능 | 무엇을 하는가 |
|---|---|
| 이미지 종류 지정 | 각 파일을 메인 이미지 / 스티커 이미지 / 탭 이미지로 직접 지정할 수 있습니다. |
| 규격 검사 | 지정한 이미지 종류의 요구 크기와 실제 이미지 크기를 비교합니다. |
| 파일 검사 | PNG 여부, 파일 용량, RGB/RGBA 컬러 모드, 투명 배경, 여백을 확인합니다. |
| OGQ 시장 비교 | 사용자가 입력한 느낌·태그를 바탕으로 관련 OGQ 공개 콘텐츠를 검색하고 비교합니다. |
| AI 진단 | 선택한 검사 기준과 시장 비교 자료를 바탕으로 개선 포인트를 정리합니다. |
| 문제 위치 표시 | AI가 특정한 문제 영역을 이미지 위에 표시해 위치를 빠르게 확인할 수 있습니다. |
| WHERE / WHY / HOW | 어디가 문제인지, 왜 중요한지, 어떻게 수정할지 구분해서 제공합니다. |
| 검사 기준 커스텀 | 기본 평가 영역을 선택하고 사용자가 직접 검사 기준을 추가할 수 있습니다. |
| 준비도 점수 | 검사 결과와 체크리스트를 바탕으로 100점 기준의 준비도 점수를 계산합니다. |
| 개선 우선순위 | 실패·주의 항목을 기준으로 먼저 수정할 항목을 정리합니다. |
| PDF 리포트 | 검사 결과와 AI 진단 내용을 PDF로 저장할 수 있습니다. |
| 히스토리 | 로그인한 사용자별로 과거 진단 결과를 저장하고 다시 볼 수 있습니다. |
| 리뷰 | 진단 결과에 대한 사용자 의견을 저장하고 공개/개발자 전용으로 관리할 수 있습니다. |

> 참고: 평가 기준은 **공개된 OGQ 제작 가이드와 프로젝트에서 정의한 기준**을 바탕으로 합니다. OGQ의 비공개 내부 심사 매뉴얼을 구현했다고 주장하지 않습니다.

## 4. 이미지 종류를 직접 지정하는 이유

이미지의 가로·세로 크기만 보고 종류를 추정하면 잘못 판단할 수 있습니다.

예를 들어 240×240px 이미지라고 해서 실제 의도가 항상 메인 이미지는 아닙니다. 그래서 현재 버전에서는 **사용자가 파일별 종류를 직접 지정하고**, 프로그램은 그 종류에 맞는 규격을 검사합니다.

현재 기준은 다음과 같습니다.

- 메인 이미지: **240 × 240px, 1개**
- 스티커 이미지: **740 × 640px, 24개**
- 탭 이미지: **96 × 74px, 1개**
- 개별 이미지 용량: **1MB 이하**

파일별로 지정한 종류와 실제 크기가 맞지 않으면 어떤 규격이 필요한지 함께 보여줍니다.

    ↓
OGQ 시장 비교

> **어디가 문제인가 → 왜 문제인가 → 어떻게 고칠 것인가**

까지 이어지는 것입니다.

## 6. AI 진단

AI 진단은 한 줄짜리 평가만 보여주지 않습니다.

### WHERE
문제가 발생한 영역을 가능한 경우 이미지 위에 표시합니다.

### WHY
해당 문제가 가독성, 완성도, 시장 맥락 등에 어떤 영향을 줄 수 있는지 설명합니다.

### HOW
사용자가 실제로 수정할 수 있도록 구체적인 개선 방향을 제안합니다.

또한 사용자가 직접 추가한 검사 기준도 AI 요청에 포함해 각 기준별 결과를 받을 수 있도록 구성했습니다.

### AI 결과 예시 구조

```text
핵심 총평
    ↓
상세 설명
    ↓
문제 1
 ├─ 어디가
 ├─ 왜
 └─ 어떻게
    ↓
문제 2
 ├─ 어디가
 ├─ 왜
 └─ 어떻게
```

문제 위치 표시는 **AI의 참고용 시각화**이며, 좌표를 특정하기 어려운 경우 위치를 억지로 표시하지 않습니다.

## 7. OGQ 시장 비교

사용자가 스티커의 **느낌·분위기·태그**를 입력하면 OGQ 공개 API를 통해 관련 콘텐츠를 검색합니다.

검색 결과를 바탕으로 AI가 다음 내용을 정리합니다.

- 시장 유사성
- 콘텐츠별 유사점과 차이점
- 시장에서 보이는 공통 요소
- 차별화되는 요소
- 보완하면 좋은 점
- 우선 확인할 항목

이 기능은 **시장 참고 분석**을 위한 것이며, OGQ 내부 심사 결과나 합격 확률을 예측하는 기능이 아닙니다.

## 8. 사용자 경험 개선 과정

이 프로젝트는 기능 구현에서 끝내지 않고 실제 배포 후 사용 흐름을 확인하면서 화면을 다시 수정했습니다.

### 확인한 문제

AI가 충분한 내용을 제공하더라도 정보가 한 화면에 많이 모이면 사용자가 핵심을 빠르게 찾기 어렵습니다.

### 개선한 부분

- AI 피드백 영역의 가독성 강화
- 핵심 단계 제목의 시각적 강조
- 문제 위치를 이미지 위에 표시
- WHERE / WHY / HOW 구조로 내용 분리
- 수정 우선순위가 눈에 띄도록 정리
- 메뉴와 히스토리·리뷰 접근 흐름 단순화

즉, **AI의 답변 자체보다 그 답변을 사용자가 실제 행동으로 옮길 수 있는 화면**에 집중했습니다.

## 10. 사용하지 않은 이유도 확인했습니다

모든 사람이 스티커 제작 도구의 대상 사용자는 아니었습니다.

사용하지 않은 이유로는 다음과 같은 의견이 있었습니다.

> “이모티콘에 관심이 없습니다.”  
> “흥미가 없습니다.”  
> “나는 이런 것을 잘 못합니다.”

![사용자 피드백](assets/user-feedback.png)

이 결과를 통해 **제품의 기능이 부족해서 사용하지 않는 경우와, 애초에 관심이 없는 사용자는 구분해서 볼 필요가 있다**는 점을 확인했습니다.

따라서 이후 개선에서는 무조건 기능을 늘리기보다 **관심이 있는 초보 제작자가 첫 화면에서 제품의 가치를 바로 이해할 수 있는가**를 중요한 기준으로 삼았습니다.

## 12. 준비도 점수와 개선 우선순위

검사 결과와 셀프 체크리스트를 합쳐 **100점 기준 준비도 점수**를 계산합니다.

현재 점수는 자동 검사와 체크리스트를 결합해 계산합니다.

```text
자동 검사 점수   70%
셀프 체크리스트 30%
        ↓
   최종 준비도 점수
```

그리고 실패·주의 항목을 모아

> **“이것부터 고치세요”**

형태로 우선순위를 보여줍니다.

점수는 **실제 OGQ 합격 확률이 아니라 프로젝트 내부의 준비도 지표**입니다.

## 16. 실행 방법

### 1) 저장소 클론

```bash
git clone https://github.com/gage9650/OGQ-Sticker-Doctor.git
cd OGQ-Sticker-Doctor
```

### 2) 패키지 설치

```bash
pip install -r requirements.txt
```

### 3) Streamlit Secrets 설정

`.streamlit/secrets.toml`에 다음 값을 설정합니다.

```toml
GEMINI_API_KEY = "your-gemini-api-key"
OGQ_API_KEY = "your-ogq-api-key"
OGQ_API_BASE_URL = "https://4th-ai-ogq.competition.ogq.me"
DEVELOPER_USERNAMES = "your-developer-username"
```

API 키와 실제 비밀값은 코드나 GitHub 저장소에 직접 올리지 않습니다.

### 4) 실행

```bash
streamlit run app.py
```

## 17. 개발하면서 바뀐 방향

처음에는 AI를 활용해 스티커를 만들어주는 방향도 고려했습니다.

하지만 이미 비슷한 생성형 도구가 많고, 단순히 “AI로 만들어준다”만으로는 제품의 역할이 분명하지 않다고 판단했습니다.

그래서 방향을 **생성 → 검사와 개선**으로 바꿨습니다.

최종적으로는

> **스티커를 대신 만들어주는 도구가 아니라, 만든 스티커를 업로드하기 전에 점검하고 개선할 수 있게 도와주는 도구**

를 목표로 삼았습니다.

## 18. 현재의 한계

### AI 판단의 한계

AI는 이미지와 전달된 자료를 바탕으로 판단하기 때문에 사람이 보는 관점과 다를 수 있습니다.

### 시장 비교의 한계

OGQ 공개 API로 확인할 수 있는 콘텐츠를 중심으로 비교하므로 전체 시장을 완전히 대표하지는 않습니다.

### 사용자 검증 규모의 한계

현재 확인된 배포 방문자 수는 17명이며, 이 수치만으로 제품의 성공 여부나 전체 사용자 반응을 일반화하기는 어렵습니다.

### 실제 심사 결과와의 차이

준비도 점수와 AI 진단은 제출 전 참고용 도구입니다. 실제 심사 결과를 보장하지 않습니다.
